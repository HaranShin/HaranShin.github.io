# 대표적 Audio 모델

| 구분 | 설명 | 대표모델 |
| :--- | :--- | :--- |
| Cascade | ASR → LLM/애플리케이션 → TTS 파이프라인 | 전통적 Voice Assistant, IVR |
| E2E (Discrete) | 오디오를 discrete token으로 변환 -> LLM이 직접 시퀀스를 생성 | GLM-4-Voice, Moshi, SpeechGPT |
| E2E (Continuous) | 오디오를 continuous representation 으로 인코딩 -> LLM에 입력 | Qwen2-Audio, LLaMA-Omni, SALMONN, AudioFlamingo3 |
| E2E (Hybrid) | discrete token과 continuous를 결합해 | MinMo, Kimi-Audio |

ASR (STT, Automatic Speech Recognition): 음성을 텍스트로 변환하는 기술



# Cascade 방식
+ ASR → LLM/애플리케이션 → TTS로 구성
    + 동작 방식: 음성 입력 ➔ **1단계: ASR** (음성을 텍스트로 변환) ➔ **2단계: LLM** (텍스트 분석 및 답변 생성) ➔ **3단계: TTS** (답변 텍스트를 다시 음성으로 변환) ➔ 음성 출력'
    + 특징: 각 단계가 폭포수처럼 순차적으로 이어지기 때문에 Cascade라고 부릅니다. (최근에는 이 단계들을 하나로 통합한 E2E, **End-to-End 모델**과 대비되어 많이 쓰입니다.)
+ 여러 독립 모듈을 순차적으로 연결하는 파이프라인 방식
+ 각 모듈(ASR→LLM→TTS)이 분리되어 있어 모듈별 교체·개선이 쉽다.
+ 앞 단계의 오류가 누적되고 음성 정보(감정·억양)가 손실될 수 있다.

# E2E (End-to-End)
+ 입력(음성)부터 출력(음성/텍스트)까지 단일 모델이 직접 처리하는 방식
+ 중간 단계 오류 누적이 없고 음성 정보를 보존할 수 있다.

### Discrete Token 과 Continuous Embedding의 간략 비교

| Discrete Token | Continuous Embedding |
| :--- | :--- |
| ▶ LLM 어휘에 그대로 추가 가능 | ▶ 이해(인식) 성능이 높음 |
| ▶ 음성 생성(출력)도 가능 | ▷ 음성 생성(출력)은 별도 장치 필요 |
| ▷ 세밀한 정보 일부 손실 | ▷ projection layer 추가 필요 |
| ▷ 코드북 크기만큼만 표현 가능 | ▶ 음색·감정·억양 세밀히 보존 |
